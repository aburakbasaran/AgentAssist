## Known Production Gaps (Out of Scope This Sprint)

The following items are **deliberately not implemented**. Production deployment beyond an internal pilot must add:

1. **Entra ID app registration + JWT bearer + policy authorization** (e.g. `Microsoft.Identity.Web`). Endpoints would gain `.RequireAuthorization("AssistantAccess")` instead of `.AllowAnonymous()`. (ADR-0010)
2. **APIM in front of App Service** with rate limiting, WAF, JWT validation, and IP allowlist.
3. **Private Endpoint / VNet integration** for App Service, Azure SQL, Azure AI Search, Azure OpenAI, and Key Vault, removing public network exposure.
4. **Production-mode anonymous fail-fast guard** at startup, ensuring the app cannot run with `.AllowAnonymous()` in `Production` environment.
5. **Automated ingestion pipeline** for knowledge documents (Azure Functions, Search indexers, or `azd` push pipelines). Current pilot uses manual `az rest` push to the Search index.
6. **Audit-or-fail policy** instead of best-effort. Current policy logs a warning and continues; an outbox pattern or transactional write would tighten compliance posture.
7. **End-to-end model alive probe** (`/health/deep`, off-by-default cron). Current `AzureOpenAIHealthCheck` deliberately avoids chat completion to control cost/quota.
8. **EF Core migration committed** under `src/AgentAssist.Infrastructure/Persistence/Migrations/`. The pilot deploy guide instructs operators to generate and apply a migration manually with `dotnet ef migrations add InitialAuditSchema`.

These are documented in:

- [`docs/quality-gates/production-pilot-quality-gate.md`](production-pilot-quality-gate.md) "Known Production Gaps".
- [`docs/adr/0010-pilot-user-context-production-auth-out-of-scope.md`](../adr/0010-pilot-user-context-production-auth-out-of-scope.md) "Out of Scope".
- [`docs/azure/production-pilot-azure-setup.md`](../azure/production-pilot-azure-setup.md) "Optional Production Hardening".

## Final Verdict

The production-ready internal pilot / reference architecture milestone is **complete**. The system demonstrates citation-first RAG over Azure AI Search hybrid retrieval, Azure OpenAI `IChatClient` with structured citation validation, persistent SQL audit, observability with custom metrics in both Mock and DevCloud, and a runnable `[Theory]`-based evaluation harness with JSON artefact, while keeping a clean Mock mode for offline use. Production exposure beyond an internal pilot requires the eight hardening steps listed above; this is by explicit design decision, not omission.

## Quality Gate Re-Review Fixes (Round 3)

A third re-review focused on observability fidelity, redaction effectiveness, doc/code drift, and `TimeProvider` discipline. The following items were closed:

| Item | Resolution |
|---|---|
| **I8** — `RedactingLogger` was a no-op (provider was registered but its logger ignored every call) | Replaced the marker provider with `SensitiveDataRedactingLoggerFactory`, an `ILoggerFactory` **decorator** that wraps every `ILogger` produced by the host. Each wrapped logger forwards the call to the inner logger but rewrites the formatter delegate through `Redact()`, so every downstream provider (Application Insights, Console, file) sees the redacted text. `RegisterDecorator` swaps the existing `ILoggerFactory` registration in the DI container only when `IHostEnvironment.IsProduction()` is true. New unit tests assert `Redact()` covers `Question` / `AnswerText` / `Content` and that the decorator actually delivers the redacted form to a captured inner logger. |
| **I2 — `agentassist.provider_mode`** | `IAgentAssistMetrics.RecordProviderMode(mode)` added; `AgentAssistMetricsAdapter` now calls `meter.ProviderModeCounter.Add(1, modeTag)` once per query inside `AnswerAssistantQueryHandler.HandleAsync` (right after `mode` is resolved). Verified by `Handler_AnyQuery_IncrementsProviderModeCounterOnce`. The dimension on the other instruments is preserved for split-by panels but is no longer the only signal. |
| **I2 — `agentassist.ai.tokens.input` / `agentassist.ai.tokens.output`** | New `Histogram<long>` instruments on `AgentAssistMeter`. `IAgentAssistMetrics.RecordTokenUsage(input?, output?, mode)` is called from `AnswerAssistantQueryHandler.RecordTokenUsageIfPresent` after every `IChatClient.GetResponseAsync` whenever `ChatResponse.Usage` is populated by the upstream `Microsoft.Extensions.AI` provider. The deterministic Mock chat client deliberately leaves `Usage = null`, so the histograms report only on real DevCloud traffic. Verified by `Handler_ChatResponseWithUsage_RecordsTokenHistograms` and `Handler_ChatResponseWithoutUsage_SkipsTokenRecording`. |
| **M7** — `production-pilot-overview.md` still described the old "header off → MockUserContextProvider" toggle | Pilot User Context Flow section rewritten around `UserContextSource` (`Header` / `Mock` / `None`), with a decision-tree mermaid diagram covering `Program.cs` startup logic, an explicit note about `AnonymousUserContextProvider` deny-by-default behaviour, and the ADR-0010 fail-fast guard for `Production + DevCloud + AllowHeaderUserContext=true`. The composition diagram was also updated to show the orthogonal `UserContextSource` axis alongside `AgentAssistOptions.Mode`. |
| **N2** — `EvaluationHarnessFixture.WriteResults` used `DateTimeOffset.UtcNow` directly | Fixture now accepts a `TimeProvider` (defaulting to `TimeProvider.System`) and threads it through `WriteResults`, which uses `timeProvider.GetUtcNow()` both for the file-name stamp and the `runStartedUtc` field of the JSON summary.
